# 茶农手账系统 API文档总览

## 概述

本文档提供茶农手账系统前端API文档的总览和规范化要求，确保API文档的一致性、清晰性和易用性。

## API文档结构

### 文档组织原则
- **模块化分离**：每个功能模块对应一个独立的API文档
- **单一职责**：每个页面只包含一个API模块的完整文档
- **层次清晰**：采用统一的文档结构和格式
- **命名规范**：文档命名与展示页面保持一致

## API文档规范

### 1. 文档结构规范

每个API文档必须包含以下标准结构：

```markdown
# [模块名称]API文档

## 概述
[模块功能简介]

## 基础信息
- **基础URL**: `/api/[module]`
- **请求方式**: POST（默认）
- **请求格式**: JSON
- **响应格式**: JSON
- **认证方式**: Header中设置auth字段

## 通用响应格式
[标准响应格式说明]

## Mock数据支持
[Mock模式说明和测试数据]

## API接口列表
[具体接口文档]

## 使用示例
[代码示例]
```

### 2. 命名规范

**文件命名规则：**
- 使用小写字母和连字符：`module-api.md`
- 与对应功能页面名称保持一致
- 避免使用空格和特殊字符

**接口命名规则：**
- RESTful风格：`/api/module/action`
- 使用动词+名词组合：`/api/auth/login`
- 保持语义清晰和一致性

### 3. 内容规范

**请求格式要求：**
- 所有请求参数使用JSON格式
- 空参数也要传递 `{}`
- Header中必须设置auth字段

**响应格式要求：**
```json
{
  "error": 0,
  "body": {},
  "message": ""
}
```

**错误码标准：**
- `0`: 成功
- `401`: 未授权，需要登录
- `500`: 系统异常
- 其他值: 业务异常

### 4. Mock数据规范

**Mock模式支持：**
- 开发环境自动启用
- UI控制开关切换
- localStorage手动设置

**测试数据要求：**
- 提供完整的测试账号
- 模拟真实的业务场景
- 包含错误处理测试

## 开发者指南

### API调用流程
1. **认证获取**：通过登录接口获取token
2. **请求构建**：设置正确的请求头和参数
3. **响应处理**：使用统一的响应处理函数
4. **错误处理**：根据错误码进行相应处理

### 最佳实践
- 使用 `createApiPromise` 统一处理API响应
- 优先使用Mock模式进行开发和测试
- 遵循RESTful API设计原则
- 保持接口的幂等性和安全性
