## Mock数据支持

### 概述
系统在开发阶段提供了完整的Mock数据支持，可以在没有后端服务的情况下进行前端功能测试。

### Mock模式启用
1. **UI切换**：在登录页面找到"Mock模式"开关
2. **手动设置**：在浏览器控制台执行 `localStorage.setItem('useMock', 'true')`
3. **默认启用**：开发环境首次访问时自动启用Mock模式

## 文档规范

### 文档结构
每个API文档必须包含以下标准结构：
1. **概述** - API功能简介
2. **基础信息** - 基础URL、请求格式、认证方式
3. **Mock数据支持** - Mock模式启用方式和测试数据
4. **通用响应格式** - 标准响应结构和错误码
5. **API接口列表** - 具体接口定义
   - 接口地址
   - 请求参数
   - 响应示例
6. **使用示例** - 前端调用示例（可选）

### 命名规范
- API文档文件名格式：`{功能模块}-api.md`
- 使用小写字母和连字符分隔
- 示例：`auth-api.md`、`dashboard-api.md`、`assets-api.md`

## 通用规范

### 请求格式
- 所有请求使用JSON格式
- 请求头必须包含`auth`字段（值为token）
- 默认请求方式为POST
- 即使参数为空，也需要传递`{}`

### 响应格式
```json
{
  "error": 0,
  "body": {},
  "message": ""
}
```

### 错误码
- `0`: 成功
- `401`: 未授权，需要登录
- `500`: 系统异常
- 其他: 业务异常

### Mock响应处理
Mock模式下，所有API都会返回统一的响应格式，包含模拟的网络延迟和完整的错误处理。
